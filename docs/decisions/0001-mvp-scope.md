# 0001：MVP 范围与验证目标

日期：2026-10-29

## 已确认的产品方向

- 面向有交易经验、但不会编程的普通 A 股投资者。
- 用户自己制定规则；产品帮助表达、检验、理解和迭代规则。
- 价值闭环是“搭规则—历史实验—查原因—修改—同条件比较”。
- 先由单人开发，先完成 MVP，再让少量真实用户试用并按阻塞迭代。
- 可信和可解释优先于展示收益；收益更高不是 MVP 的自动验收标准。

## 本阶段采用的默认范围

为尽快建立可测试闭环，首版先采用：

- 单标的、日线、只做多、不加杠杆；
- 少量已测试的价量条件、入场、退出和仓位卡片；
- Python 引擎独立于 API、UI 和模型；
- 前端/接口技术栈暂按 React + TypeScript + Vite、Python + FastAPI/Pydantic、SQLite 规划；
- 先使用自编合成数据验证计算，再核查真实数据授权和质量。

这些是当前实现假设，不是对最终技术选型、商业模式或真实数据供应的承诺。若要改变，须在决策文档中记录原因和影响。

## v0.1 必须完成

1. 固定数据/标的/研究区间/保留检验区间。
2. 有限条件卡片和可读规则确认单。
3. 确定性历史实验，区分失败、无交易、亏损和正常完成。
4. K 线、交易标记和逐日 DecisionTrace 联动。
5. 解释为何触发、为何未触发、为何触发但未成交。
6. 从旧规则复制出新版本，记录修改理由并保留旧运行。
7. 相同条件下比较两版规则、交易变化和结果变化。
8. 保存、恢复、导出规则和运行摘要。

## 明确不纳入 v0.1

全市场动态选股、多标的组合、任意代码、自由 DAG、机器学习预测、实时舆情、盘中路径、自动下单、自动调参、策略商城和完整支付体系。

## 成功判定

工程成功：输入快照、计算结果和解释记录一致、可复现、可测试。

用户成功：不用编程的目标用户能够搭出一条规则，解释一次交易和一次无交易，发现一个意外，修改出新版本，并说明两版差异。
