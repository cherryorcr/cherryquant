# 0002：首版交易与解释语义

日期：2026-10-29

这是引擎和所有上层界面共同遵守的契约。UI、API 或模型不得临时改变这些含义。

## 时序

- 仅在日线收盘数据完整后观察条件。
- 收盘产生的信号最早在下一交易日开盘尝试模拟成交。
- 首版订单只对下一交易日有效；无法成交就记录原因并取消。
- 没有下一交易日时不虚构成交。

## 范围与持仓

- 单标的、只做多、不加杠杆。
- 订单、现金、手数、仓位上限、费用和持仓状态都要参与计算。
- 对普通 A 股按 T+1 处理；不把其他品种的当日回转规则套用进来。
- 持仓存在时先处理退出，不在同一撮合时点又退出又重新入场。

## 不确定性与限制

- 缺数据、指标预热不足、条件不成立是不同状态，不能都变成 `false`。
- 停牌、价格限制、现金不足、手数约束等造成的未成交要记录具体原因。
- 首版不推断同一天内止盈和止损的先后；不支持的盘中路径必须明确拒绝。
- 价格口径、复权、公司行为、费率和交易限制要写进 DataSnapshot/ExperimentConfig；不支持的历史场景不能静默忽略。
- 期末仍持仓时区分浮盈估值和已实现收益，不制造不存在的平仓成交。

## 事件分层

`condition_evaluation` → `signal` → `order_attempt` → `fill`/`not_filled`。

解释面板只读实际运行生成的 `DecisionTrace`，不能为了让结果更好看而重新计算或由模型编造理由。
